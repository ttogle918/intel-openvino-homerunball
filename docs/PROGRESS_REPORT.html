1. 프로젝트와 시연 시나리오

한 줄 소개: SO-ARM101 로봇팔이 섞인 트레이에서 목표 과자(지금은 오란다)만 골라 빈 트레이로 옮기고, 채팅·음성으로 일을 시키며, 몇 번 하면 지쳐서 도리도리로 거부하고 달래면 다시 일하는 해커톤(2일) 프로젝트.

  • 하드웨어: SO-ARM101 (팔로워 1대, 학습용 리더 1대), 카메라 3대(외부 + 손목, 사이드 캠 추가)
  • 소프트웨어: physical-ai-studio로 학습한 ACT(OpenVINO 결과물, physicalai 런타임), LLM(API 또는 로컬), TTS, STT, FastAPI + 웹 UI

시연 시나리오

  1. 섞인 트레이를 놓고 채팅 또는 음성으로 "오란다 3개 옮겨줘"라고 시킨다 (IDLE → WORKING).
  2. 로봇(캐릭터 이름 "보리")이 oranda_pickup ACT 정책으로 한 개씩 옮긴다. 코드가 횟수를 센다.
  3. 몇 번 하면 피로도 기준을 넘어 dori_dori 정책(고개 젓기)으로 거부한다 (REFUSING).
  4. 사용자가 달래면(채팅·음성·r 키) 다시 일한다. 목표 개수를 채우면 DONE → IDLE.
  5. 언제든 space(또는 UI 버튼)로 비상정지. 토크를 유지한 채 자세를 고정한다.

5-A. 설계 마일스톤

M0 환경 확인 완료

무엇: 로봇 코드를 쓰기 전에 physicalai 시그니처, 카메라 이름, Studio 설정을 확인하는 단계.

만든 것: 설계 문서 11.5절. dori-dori 결과물 exports/openvino(act.xml, act.bin, manifest.json) 입력은 state(6), images.tower cam, images.follow cam(각 3x720x1280), 전처리 letterbox 384x384, 출력 action (100, 6), chunk_size = n_action_steps = 100. Studio(192.168.0.6:7860)의 카메라 UVC 번호와 로봇 포트도 조회 API(GET)로만 읽었다.

왜: 이 PC에는 physicalai가 없어서 추측으로 로봇 코드를 쓰지 않으려고 계획을 둘로 나눴다(결정 20). 카메라 이름이 학습 때와 정확히 같아야 하므로(images.<cam>) 처음에 가정한 front/wrist를 실제 이름으로 바꿨다.

확인: 설계 문서 11.5절 읽기. 미확인으로 남은 것은 12장(노트북의 OpenVINO 디바이스 문자열 등).

주의: 카메라 이름 불일치(Studio에서 A/B 같은 이름일 수 있음)는 skills.oranda_pickup.camera_map으로 학습 이름을 config 이름에 매핑하도록 설계.

M1 핵심 흐름 (B 판정, dry-run, 콘솔) 완료

무엇: 로봇 없이 시작 → 작업 → 거부 → 재개 → 완료까지 도는 최소 흐름.

만든 것: controller.py(상태 머신, 루프 스레드, 명령), brain.py(가드 규칙), skills.py(DrySkills), 콘솔 키(s 시작, r 재개, space 비상정지, h 재시작, q 종료), 사이클별 JSONL 로그(logs/).

동작: B 판정은 시작 개수(채팅의 n 또는 target.initial_count) + 그리퍼 쥠 판정. 성공 = 닫힘 구간 그리퍼 최솟값이 grasp_min 이상(빈 그리퍼는 끝까지 닫힘). 횟수는 코드가 센다.

왜: ACT는 "이제 과자가 없다"를 모르고 성공 여부도 모른다. 끝낼 시점과 성공 판정은 코드 몫(결정 16). 한계: 다른 과자를 집어도 성공으로 센다. 그래서 UI는 B일 때 "추정"으로 표시.

확인:

.venv/Scripts/python -m snackbot --dry-run --no-ui
.venv/Scripts/python -m pytest tests/test_controller.py tests/test_brain.py -q

주의: dry_run.fail_rate로 실패를 주입해 재시도·운영자 대기 흐름도 시험할 수 있다. 남은 minor는 8장 참고.

M2 서버 + 웹 UI 완료

만든 것: server.py (FastAPI: /ws, /stt, /stream/front MJPEG, frontend/ 정적 서빙), frontend/ (index.html, app.js, style.css; Claude Design 결과물: 채팅, 음성, 피로도 게이지, 카메라, 성능, 진행자 버튼).

동작: WebSocket 하나로 통신한다. 서버 → 화면: info, state, message, cycle. 화면 → 서버: chat, command(resume | estop | restart). 화면은 서버가 돌려준 메시지로만 그린다(기록이 controller 한 곳). 접속 직후 info·state와 최근 message 50개를 보내 새로고침해도 대화가 남는다.

왜: Gradio/Streamlit 대신 FastAPI + 빌드 없는 정적 파일(시연 PC에 Node 불필요, 디자인 자유도). UI가 죽어도 콘솔 space 비상정지는 계속 동작(결정 1, 4, 6).

확인:

.venv/Scripts/python -m snackbot --dry-run --host 127.0.0.1 --port 8000
# 브라우저: http://127.0.0.1:8000  (마이크는 localhost에서만 권한이 난다)

주의: Windows에서 tests/test_server.py가 WinError 10014(루프백 소켓)로 한 번에 1~3개 가끔 실패한다(알려진 문제, 다시 돌리면 통과). 서버 시작도 같은 이유로 가끔 실패해 재시도가 필요하다.

M3 provider · brain · TTS · counter 체인 완료

만든 것: providers.py(openai_compat / anthropic / openvino 어댑터 + fallback 체인), brain.py(decide, chat), voice.py(비동기 TTS), vision.py(counter 체인), tools/export_yolo_world.py.

동작: 역할(brain, vision, stt)마다 provider 체인을 순서대로 시도하고 타임아웃(brain 기본 5초 이상, 현재 설정 8초)을 둔다. 전부 실패하면 키워드 규칙으로 결정해 로봇 루프는 멈추지 않는다. counter 체인은 YOLO-World(제로샷 텍스트 클래스) → VLM → OpenCV(면적 + 황갈색 HSV) 순서이며 config로 바꾼다. A가 실패한 사이클은 B로 대체.

왜: 파인튜닝 없음 규칙(개수 세기는 제로샷). openai_compat 어댑터 하나로 OpenRouter, NVIDIA, OpenAI, Gemini, Groq, Ollama를 base_url과 키만 바꿔 쓴다(결정 12, 15).

확인:

.venv/Scripts/python -m pytest tests/test_providers.py tests/test_brain.py tests/test_vision.py tests/test_voice.py -q
.venv/Scripts/python -m snackbot.vision tests/samples/tray_3.jpg

주의: 현재 vision.chain은 빈 목록이라 B단계로만 동작한다. 실제 YOLO-World/VLM은 이 PC에 ultralytics 등을 설치하지 않았기 때문에 검증하지 않았다(남음 항목).

M4 로봇 연결 진행 중

무엇: physical-ai-studio가 학습한 ACT OpenVINO 정책 2개를 physicalai 0.3.0 런타임으로 SO-101에서 직접 실행. 그리퍼 "닫힘 → 열림"에서 ACT를 멈추고 코드가 lift_pose → home_pose로 복귀, 비상정지는 토크 유지.

구조(계획): RobotRuntime 하나를 시작 때 연결해 두고 run()마다 동작 출처를 바꿔 끼운다(Switch.active = 정책 A / 정책 B / MoveSource). 매 틱 콜백(Tap)이 관절값·프레임을 저장하고 GripperWatch에 넘긴다.

왜 그리퍼 전이인가: 홈 자세에서 그리퍼가 이미 열려 있으면 "열림 + 0.5초"는 시작하자마자 걸린다. 닫힘 기준을 한 번 지난 뒤 열림 기준을 0.5초 넘으면 정지, 최대 시간은 안전장치(결정 17). 기준값은 tools/gripper_stats.py로 데이터셋에서 정한다.

Task별 상태: Task 1 완료(아래), Task 2~6 남음(아래 5-C).

왜 로컬 Whisper: 코드(OpenVINOProvider(kind="whisper"))가 이미 있고, 노트북 안에서 돌아 네트워크·크레딧에 영향받지 않으며, 실습 자료의 "on-device, no external API" 평가 항목에도 맞는다(결정 21).
