로봇 실행과 화면 대비책

2026-10-22 의논 정리. Studio와 우리 서버가 각각 무엇을 하는지, 카메라는 어떻게 연결하는지, 로봇·모델이 안 될 때 화면을 어떻게 보여 줄지. 설계 확정 대기

한 줄 요약
  • Studio는 학습·내보내기에만 쓴다. 시연 때 로봇·카메라·추론은 우리 서버(snackbot)가 노트북 안에서 직접 돌린다.
  • 그래서 카메라 영상과 3D 팔은 Studio가 아니라 우리 웹 화면(http://localhost:8000)에서 보여 준다.
  • 로봇·모델이 안 될 때를 대비해, 화면을 4분할(카메라 3 + 3D 1)로 만들고 Studio에 녹화된 에피소드(영상 + 관절 궤적)를 재생할 수 있게 한다.

1. Studio와 우리 서버의 역할

Studio: 데이터 녹화→ Studio: ACT 학습→ Studio: OpenVINO로 내보내기
exports/openvino→ 노트북에 복사→ 우리 서버가 physicalai 런타임으로 실행
단계어디서설명
녹화 · 학습 · 내보내기Studio리더 팔로 시연을 녹화하고 ACT를 학습한 뒤 act.xml / act.bin / manifest.json으로 내보낸다.
캘리브레이션 받기Studio → 노트북 (처음 한 번)python -m tools.fetch_calibration. 조회(GET)만 한다. 녹화 때와 같은 캘리브레이션이어야 정책이 맞게 움직인다.
녹화 에피소드 받기Studio → 노트북 (선택, 한 번)대비책 재생용. 조회 API가 에피소드의 관절값과 카메라 영상을 준다.
시연 (추론 실행)우리 서버로봇·카메라 연결, OpenVINO 추론, 그리퍼 정지 판단, 복귀, 비상정지, 채팅·음성·거부·달래기 흐름 전부.

시연 중에는 Studio를 꺼 둔다. 로봇 USB 포트와 카메라는 한 프로그램만 잡을 수 있기 때문이다.

2. "Studio 화면을 iframe으로 넣으면 안 되나?"

정책상 막힌 건 아니다. Studio 코드에는 다른 페이지 안에 넣는 것을 막는 헤더(X-Frame-Options, CSP frame-ancestors)가 없어서 localhost:7860 화면을 iframe으로 띄우는 것 자체는 된다. 걸리는 건 기술적인 조건이다.

동시에 같은 로봇·카메라를 볼 수 없다

누가 추론을 돌리나우리 화면 (8000)Studio 화면 (7860)
snackbot (시연 기본)✔ 카메라 3대 실시간 + 3D 팔이 실제 관절을 따라 움직임✘ Studio가 로봇·카메라에 연결할 수 없어 빈 화면
Studio 추론 화면✘ 우리는 로봇을 못 잡음✔ Studio 화면은 나오지만 우리 흐름(채팅·거부·비상정지·그리퍼 정지·복귀)이 빠짐

로봇 없이 대비할 때의 iframe 한계

  • Studio에서 3D 팔이 나오는 화면은 추론 화면과 로봇 화면뿐이고, 둘 다 Studio가 로봇에 연결해 있어야 움직인다. 녹화 에피소드 화면에는 3D가 없어 보인다 (코드 기준, 실제 화면 확인 필요).
  • 포트가 다르면(7860 ↔ 8000) 다른 출처라 우리 쪽에서 그 화면을 조종할 수 없다 → "옮길 차례에 재생 시작" 같은 동기화가 안 된다.
  • 화면의 일부만 잘라 넣을 수 없다 (메뉴 포함 전체가 들어온다).

결론: 데이터는 Studio API에서 받아 오되 화면은 우리가 그려 사이클과 시간을 맞춘다. 그래도 Studio 화면이 필요하면 4분할 중 원하는 칸에 iframe URL을 넣는 옵션을 둔다.

3. 카메라 연결: USB만 꽂으면 되나?

반만 자동이다. 서버는 시작할 때 config.yaml에 적힌 카메라를 자동으로 열어 화면에 띄운다. 다만 "어느 USB 카메라가 tower cam인지"는 처음 한 번 알려 줘야 한다.
  • 왜 자동으로 못 하나: 모델은 학습 때 tower cam, follow cam(과자 모델은 사이드 캠 포함)이라는 이름으로 카메라를 구분해 배웠다. 카메라가 서로 바뀌면 모델이 엉뚱한 시점을 보고 이상하게 움직인다.
  • 번호 vs 시리얼: 지금 config는 번호(device: 0 → /dev/video0)다. USB를 다시 꽂거나 재부팅하면 번호가 바뀔 수 있다. physicalai는 카메라를 시리얼 번호로 지정할 수 있다 → 꽂는 순서가 바뀌어도 같은 카메라를 찾는다.

추가할 도구 (노트북에서 처음 한 번)

python -m tools.cameras
  1. 연결된 카메라마다 번호 · 이름 · 시리얼을 출력하고, 사진 한 장씩 cameras/<번호>.jpg로 저장한다.
  2. 사진을 보고 어느 것이 tower / side / follow 인지 확인한다.
  3. config.yaml에 시리얼로 적는다. 예: tower cam: {device: {serial: "..."}}

4. 화면 구성: 4분할

tower cam위에서 내려다본 트레이
side cam옆에서 본 모습 (과자 모델용)
follow cam팔을 따라가는 카메라
3D 팔 (디지털 트윈)SO-101 3D 모델이 관절값대로 움직임
  • 3D 모델: TheRobotStudio SO-ARM100 저장소의 SO-101 URDF + STL (Apache-2.0, 약 19MB). three.js + urdf-loader로 그리며, 파일을 프로젝트에 넣어 오프라인에서도 돈다.
  • 좁은 화면에서는 세로로 쌓인다. 원하는 칸은 config로 iframe URL로 바꿀 수 있다.

5. 상황별로 무엇을 보여 주나

상황카메라 3칸3D 칸
다 잘 됨 (실제 로봇)실시간 영상실제 관절값을 따라 움직임 (초당 약 15번)
로봇·카메라가 안 됨 (dry-run 대비책)Studio 녹화 영상 (그 스킬의 에피소드 1개)같은 에피소드의 관절 궤적을 영상과 시간을 맞춰 재생
녹화 데이터도 없음샘플 사진홈 자세로 정지
전부 안 됨백업 영상 재생 (런북)
  • 재생은 "옮기기 · 도리도리를 할 차례"에 시작한다. 대사 소리를 기다리는 몇 초와 자연스럽게 겹친다.
  • 스킬마다 가장 잘 된 에피소드 1개를 config로 지정한다 (replay: {dataset, episode}).
  • 녹화 궤적으로 실제 팔을 움직이지는 않는다. 화면에 보여 주는 용도만.
  • ACT 정책을 시뮬레이션 안에서 돌리지는 않는다 (정책은 실제 카메라 영상을 보고 움직이는데, 시뮬레이션 화면은 학습 때 본 영상과 달라 동작하지 않는다).

6. 실행 기록 저장

  • 스킬 1회 실행마다 logs/runs/<시각>_<스킬>/에 관절값(30Hz, JSON)과 카메라 3대 프레임(10fps, 640px JPEG)을 저장한다. 20초 동작 1회 약 20~30MB, config로 끌 수 있다.
  • 녹화 재생과 같은 형식이라 같은 4분할 화면에서 다시 볼 수 있다 → 노트북 실기에서 잘 된 한 번을 저장해 두면 그대로 시연 대비 영상이 된다.

7. 설계 항목 (확정 대기)

#항목내용
14분할 화면카메라 3 + 3D 1, frontend/twin.js, three.js·urdf-loader를 frontend/vendor/에 고정 버전으로
2실제 로봇 모드/stream/{카메라 이름}으로 3대 스트림, WebSocket joints 메시지로 관절값(라디안)
3dry-run 녹화 재생acting 단계에서 replay 메시지 → 영상 3개 + 3D 동기 재생, 가짜 동작 시간 = 에피소드 길이
4녹화 받기 도구python -m tools.fetch_replays --studio URL --dataset ID --skill 이름 --episode N (GET만, replays/는 git 제외)
5관절 변환normalized → tick(physicalai와 같은 식) → 라디안, 관절별 부호·영점 보정값 config
6오류 처리3D·영상이 안 되면 그 칸만 대체, 나머지 화면과 로봇 루프는 그대로
7테스트변환식, 녹화 받기(가짜 HTTP), 서버 메시지·스트림, 동작 시간. 3D는 브라우저로 확인
8실행 기록 저장위 6절
9칸별 iframe 옵션config로 원하는 칸에 Studio 등 URL
10카메라 찾기 도구위 3절, 시리얼로 지정

8. 확인이 필요한 것

  • Studio 녹화 영상의 코덱 (LeRobot 기본 AV1일 수 있음 → Chrome은 재생 가능, 노트북 브라우저 확인).
  • 3D 팔과 실제 팔의 관절 방향·영점 (config 보정값으로 맞춘다).
  • 녹화 받기는 Studio와 같은 네트워크(노트북)에서만 된다. 개발 PC에서 보려면 받은 replays/ 폴더를 복사한다.
